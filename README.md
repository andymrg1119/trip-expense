# 拆伙

**拆伙**是一个**纯静态、零依赖、零构建**的单页网页小工具，给「几户人家一起出国旅游」的场景用：
旅途中谁垫付了什么随时记下来，最后一键算出：**每户家庭到底该出多少钱、谁该转给谁**。

> 全程数据保存在你自己的浏览器里（不上传云端），也可以导出 JSON 备份或分享。

---

## 一、怎么打开

### 方式 A：直接双击（最简单）
双击 `index.html` 即可在浏览器里使用。无需安装任何东西、无需联网。

### 方式 B：部署到 GitHub Pages（团队共享链接 / 可安装到手机）
1. 在 GitHub 新建一个仓库（或使用已有仓库），把本目录下**全部文件**上传到仓库根目录（保持相对路径）：
   `index.html`、`styles.css`、`calc.js`、`app.js`、`README.md`、
   `manifest.webmanifest`、`sw.js`、`icon-192.png`、`icon-512.png`、`icon.svg`。
2. 进入仓库 **Settings → Pages**：
   - **Source** 选择 `Deploy from a branch`
   - **Branch** 选择 `main`（或 `master`），目录选 `/ (root)`，保存。
3. 稍等 1–2 分钟，访问 `https://你的用户名.github.io/仓库名/` 即可。

> 由于全部是静态文件、且使用相对路径引用，GitHub Pages 可直接运行，无需任何构建/配置。

### 已支持 PWA（可离线 / 可"添加到主屏幕"）
- 本应用内置 `manifest.webmanifest` 与 `sw.js`：**在 https 环境下（含 GitHub Pages）会自动注册 Service Worker**，
  首次打开后即便断网也能使用，并可在手机/电脑浏览器里"添加到主屏幕"当作 App 打开。
- 在 `file://` 直接双击打开时不会注册 Service Worker（浏览器限制），但功能完全正常。
- 离线缓存的资源即上方列出的全部文件；数据仍保存在浏览器本地（localStorage），注意备份。

## 二、五分钟上手

页签从左到右依次是：**费用记录 · 结算汇总 · 家庭与成员 · 家庭明细 · 数据管理 · 我的旅程**
（每次打开默认停在最左边的「费用记录」）。首次使用建议按下面顺序上手：

1. **我的旅程**：每一次出游都是一个**独立旅程**，各自的家庭、成员、费用完全分开、互不影响。
   在这里新建 / 切换 / 重命名 / 删除旅程；顶栏也放了一个下拉框，可随时切换当前旅程。
2. **家庭与成员**：先添加几户家庭（如「张家」「李家」），再往每户里添加成员，
   并选好类型（成人 / 老人 / 小孩）。类型会影响「门票分档」和「按家庭均摊」。
3. **费用记录**：每发生一笔开销就点「+ 新增费用」，填写：日期、项目、类别、
   金额、币种、汇率、付款人、参与成员，以及**分摊方式**。
   勾选参与成员时，可用顶部「全选（共 N 人）」一键选取全部，或点每户标题行的「全选」整户勾选；
   家庭全选 / 总全选支持「部分选中」的半选状态，勾选状态实时回算。
4. **结算汇总**：查看每户「应分摊 / 已垫付 / 净额」，以及**转账方案**（谁转给谁多少钱）。
   每户卡片的**第一行**就是「条目明细」入口，点开就能看到这一家的每一笔：参与了什么、分摊多少、谁付的钱。
   需要留档就点「打印结算单」。
5. **家庭明细**：选中某一户，查看它完整的逐笔条目清单（含占比、垫付、分摊合计），适合逐户核对。
6. **数据管理**：维护**币种与汇率**、维护**费用类别**、导出/导入 JSON 备份、清空费用记录。

> 首次打开会自动载入一套**示例旅程**（3 户家庭、8 名成员、7 笔费用，覆盖全部 5 种分摊方式），
> 可以直接看效果；点「数据管理 → 清空费用记录」即可把示例里的费用都清掉（家庭、成员、币种、类别都保留），换成自己的消费；其它旅程不受影响。

## 三、五种分摊方式

| 分摊方式 | 适用场景 | 说明 |
|---|---|---|
| **按人头均摊** | 团队晚餐、打车 | 项目金额在所有参与成员之间等分 |
| **门票分档** | 景区门票 | 分别填写成人 / 老人 / 小孩单价，按每个人的类型定价累加 |
| **酒店房间** | 住宿 | 一间房可以多人（如 3 人）同住，房价在入住人之间均分 |
| **按家庭均摊** | 租车、包车 | 金额先在参与家庭之间平分，再在家庭内部平分 |
| **自定义金额** | 代购、各买各的 | 为每位参与成员单独填写金额 |

> 若「门票单价合计 / 房价合计 / 自定义合计」与项目总额不一致，
> 系统会**按比例自动调整**，并在结算页给出提示，避免算错。

## 四、结算与转账是怎么算的

- 所有费用先按各自汇率**折算成基准货币**（默认人民币），再参与分摊。
- 每个家庭的 **净额 = 已垫付 − 应分摊**：
  - **净额 > 0（红色「应收」）**：这户垫得多，别人要还给他；
  - **净额 < 0（绿色「应付」）**：这户欠着，需要补付给别人。
- 转账方案用「最大债务 / 最大债权」贪心配对，**转账笔数尽量少**，并且保证**完全平账**。

### 每户的「条目明细」怎么看

有两个地方可以看某一户的逐笔账：**结算汇总**里每户卡片的第一行点开「条目明细（共 N 笔）」，
或者到**家庭明细**页签选中某一户看完整清单。每行是一笔费用：

| 列 | 含义 |
|---|---|
| 本笔总额 | 这笔费用折算成基准货币后的总额 |
| **本户分摊** | 这一户在这笔里应承担的部分 |
| 本户占比 | 本户分摊 ÷ 本笔总额 |
| 付款人 | 这笔钱是谁付的（姓名 + 家庭） |
| **本笔本户垫付** | 若这笔钱是本户的人付的，就是该笔总额；否则为 0 |

一笔费用会计入某户的条目，只要满足「**这户有人分摊**」**或**「**这笔钱是这户的人付的**」。
所以两种情况都看得见：别人付的钱、你家分摊；以及你家付的钱、别人分摊。

条目表底部的「本户分摊合计」精确等于卡片上的「应分摊」，「本户垫付合计」精确等于「已垫付」——
明细和汇总两处永远对得上，可以拿它对账。

### 关于精度（重要）
全程以「分」为最小单位做整数运算：
- 每笔费用的各成员分摊额**之和与该笔总额完全相等**，不会出现 0.01 的丢失或溢出；
- 转账方案可精确到分地平账。

## 五、数据与备份

### 存储位置与多旅程

- 全部旅程保存在浏览器 `localStorage` 的 **`trip-expense-data-v2`** 键里（键名沿用不变），结构为
  `{ version: 2, activeTripId, trips: [ 旅程, ... ] }`；每个旅程内部沿用原字段
  （`tripName` / `baseCurrency` / `currencies` / `families` / `members` / `expenses`），
  本轮新增每旅程独立的 `categories`（费用类别列表），
  另外多出 `id` / `createdAt` / `updatedAt` 三个元字段。
- 如果你以前用过旧版本，浏览器里可能还留着旧键 **`trip-expense-data-v1`**（单个行程）。
  新版**首次打开时会把它的内容自动迁移成「1 个旅程」写入 v2**；
  旧键**只读保留、绝不删除**，所以随时可以回退，也不会丢数据。
  迁移是幂等的：一旦 v2 存在，就不会再迁移第二次。
- 换设备、清理浏览器缓存前，建议先导出备份。
- 若浏览器禁用了 `localStorage`（个别 `file://` 环境），页面会弹出红色提示条告诉你
  「本次修改只在当前页面生效」，此时请立即用导出功能保存下来。

### 费用类别（可自定义）

费用类别是**按旅程独立保存**的（存在该旅程的 `categories` 字段里），默认提供
**门票 / 住宿 / 餐饮 / 交通 / 购物 / 其他** 六类。在**数据管理 → 费用类别**里可以：

- **新增**：填类别名 →「新增类别」；重名会被拦下。
- **重命名**：点行内「重命名」就地编辑（Enter 保存 / Esc 取消），
  会**级联**把已有费用里用到的旧类别名一并改写，历史数据不会丢。
- **删除**：删除时会先确认；类别至少保留一个（删到只剩一个时会被拒绝）。
  被删除类别下的历史费用会**自动归到「其他」**（若没有「其他」则归到第一个类别）。

> 旧费用若引用了已不在当前列表里的类别，编辑这笔费用时下拉框会显示为
> **「xxx（已停用）」**，原值不会丢失，可随时改选到现有类别。

### 导入 / 导出

| 操作 | 作用 |
|---|---|
| **导出 JSON** | 只导出**当前旅程**（文件名 `行程名-记账数据.json`），可用于单独分享某一次出游 |
| **导出全部旅程** | 导出**整个旅程库**备份（文件名 `行程库备份-YYYYMMDD.json`） |
| **导入所选文件** | 自动识别两种格式：整库备份直接整体追加；单个行程则包成**一个新旅程**追加 |

> **导入只新增、绝不覆盖**：无论导入哪种格式，已有的旅程都不会被改动或删除，
> 导入进来的内容一律作为新旅程追加，并自动切换到导入后的旅程。
> 若文件损坏或格式不对，页面会弹出红色提示条说明原因（不会静默失败）。

### 清空

- **清空费用记录**：只清空**当前这一个旅程**的「费用记录」（保留旅程名称、家庭与成员、币种与汇率、费用类别），
  其它旅程完全不受影响；出于安全考虑需要**连续确认两次**。
  > 若当前旅程没有任何费用记录，点击会直接提示「当前旅程没有费用记录」而不会弹出确认框。

## 六、常见问题

**Q：换了一台电脑，数据还在吗？**
不在。数据只存在本机浏览器里。请先导出 JSON，在新设备上导入。

**Q：汇率怎么填？**
填「1 单位外币约等于多少人民币」。例如 100 日元 ≈ 4.85 元，就填 `0.0485`；
美元 ≈ 7.2 元就填 `7.2`。

**Q：为什么结算里有人是红字、有人是绿字？**
红色是「应收」（这户垫得多，别人该还他），绿色是「应付」（这户还欠着，要补付）。

**Q：金额小数很多怎么办？**
金额保留 2 位小数（精确到分）。多出的尾差会自动、精确地分配到分，不会漏掉。

## 七、技术说明

- 技术栈：原生 HTML + CSS + JavaScript（ES5/ES6 兼容），**无框架、无依赖、无构建**。
- 文件结构：

  | 文件 | 作用 |
  |---|---|
  | `index.html` | 页面结构（6 个标签页：费用记录 / 结算汇总 / 家庭与成员 / 家庭明细 / 数据管理 / 我的旅程） |
  | `styles.css` | 全部样式，含移动端与打印样式 |
  | `calc.js` | 核心算法（纯逻辑，UMD，可在 Node 中直接测试） |
  | `app.js` | 界面交互、多旅程库、表单增删改、持久化、导入导出 |
  | `README.md` | 本说明 |

- **多旅程状态约定**：`state.library` 是旅程库，`state.data` **恒指向当前旅程对象本身**
  （与 `state.library.trips` 中的元素是同一引用），因此切换旅程只需换引用并重渲染。

- `calc.js` 导出：`validateData`、`allocateExpense`、`computeResult`、`convertToBase`、`newId`。
- `app.js` 依赖 `calc.js` 的返回结构（`perFamily` / `perMember` / `perExpense` / `transfers` / `byCurrency` /
  `byCategory`），改动算法时请一并核对。

> ⚠️ **`index.html` 请用纯文本编辑器修改，不要用「所见即所得」方式编辑后保存。**
> 可视化编辑会把运行后的页面内容回写进文件（并注入大量 `data-page-node-id` 属性），
> 曾出现过页头元素被误删、导致页面报错的情况。若要调整结构，直接改 HTML 源码更稳妥。

### 在 Node 中做算法自测
```js
const TripCalc = require('./calc.js');
const data = require('./你的数据.json');
console.log(TripCalc.computeResult(data));
```
